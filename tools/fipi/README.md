# Импортер открытого банка ОГЭ ФИПИ

Собирает задания по математике из [открытого банка ФИПИ](https://oge.fipi.ru/bank/index.php?proj=DE0E276E497AB3784C3FC4CC20248DC0),
раскладывает их **по номерам заданий экзамена (1–25)** и складывает результат в
`out/tasks.jsonl` плюс папку с картинками.

Сортировки по номерам у ФИПИ нет — банк размечен только по кодификатору. Её
восстановление и есть смысл этого инструмента.

Только стандартная библиотека Python 3.10+. Ставить нечего.

## Как запускать

```bash
cd tools/fipi

python3 run.py crawl     # 39 запросов, кладёт сырой HTML в cache/
python3 run.py build     # cache/ -> out/tasks.jsonl с номерами заданий
python3 run.py images    # 2765 схем -> out/images/<guid>/
python3 run.py stats     # отчёт по классификации
```

`crawl` кэширует страницы на диск. Повторный запуск читает кэш и в сеть не
ходит — `build` можно гонять сколько угодно, переписывая классификатор.
Чтобы обновить кэш: `python3 run.py crawl --refresh`.

Полный проход занимает пару минут на `crawl` и около десяти на `images`.

### Полезные флаги

```bash
python3 run.py --theme 7 crawl              # только геометрия
python3 run.py --theme 8.2 crawl            # только вероятность
python3 run.py --answer-kind ILI_STD_FULL crawl   # только часть 2
python3 run.py --delay 3 crawl              # медленнее, если ФИПИ тормозит
```

## Результат на полном банке

3884 задачи, 1577 из них со схемами (40.6%).

| Уверенность | Задач | Доля |
|---|---:|---:|
| `certain` | 2665 | 68.6% |
| `likely` | 909 | 23.4% |
| `ambiguous` | 310 | 8.0% |

Номер стоит у **3574 задач**. Спорными остаются 310, и это почти целиком одна
причина:

- **302** — пара 23/25. Обе позиции это геометрия с развёрнутым ответом на одном
  и том же КЭС; спецификация различает их только уровнем сложности, которого в
  банке нет. Задание 24 отделяется чисто — по слову «докажите». Эти задачи
  лежат в отдельной корзине `23/25`, а не под одним из двух номеров: выбрать
  один — значит напечатать монетку как факт.
- **8** — остаток практического блока: одна группа («баня»), где порядок ФИПИ
  сломан и сценария под неё нет. Опознан только первый вопрос серии.

Практический блок 1–5 раскладывается по местам (`fipi/practical.py`), хотя из
одного условия это невозможно: позиция берётся из группы, см. ниже.

## Как устроена классификация

Три сигнала по убыванию надёжности, `fipi/classify.py`:

1. **Тип ответа.** «Развернутый ответ» встречается только в части 2, то есть
   ограничивает ответ номерами 20–25, а всё остальное — номерами 1–19.
   «Установление соответствия» в математике ОГЭ бывает практически только в №11.
2. **Текстовые сигнатуры.** Несколько позиций имеют фиксированную формулировку,
   которую банк повторяет сотнями: «на клетчатой бумаге» → №18, «Какое из
   следующих утверждений является истинным» → №19, «Пользуясь этой формулой»
   → №12.
3. **Подтемы кодификатора.** Спецификация 2026 (`research/fipi-2026/spec.txt`)
   задаёт КЭС для каждой позиции; обратная таблица превращает код в список
   кандидатов. Банк размечает большинство задач до подтемы («7.4 Окружность и
   круг»), и это самый сильный сигнал: 7.2 → №15, 7.3 → №17, 7.4 → №16,
   3.1 → №9, 3.2 → №13, 2.1 → №12.

Ничьи внутри геометрии добиваются подсчётом ключевых слов, а если и он не дал
перевеса — предметом задачи: фигура, вписанная в окружность, размечена обеими
подтемами сразу, и банк такие задачи кладёт в №16, о треугольнике там речь или
о трапеции. Что не разошлось — помечается `ambiguous`, а не угадывается.

### Блок 1–5: позиция берётся из группы

Пять вопросов задаются к одному тексту, и по самому вопросу узнать его номер
нельзя. Но группа известна: каждая запись несёт
`title="Задание N в B64540"`, то есть текст-хозяин и свой индекс в нём. Индекс —
не номер экзамена (в группе лежит несколько параллельных вариантов подряд), но
это собственный порядок ФИПИ, и варианты уложены блоками:

    номер = ceil(позиция · 5 / размер группы)

Размеры групп кратны пяти (19 групп по 5, 13 по 10, 3 по 20, по одной на 30 и
40, одна битая на 4). Правило не берётся на веру: блок всегда открывается
вопросом «какими цифрами обозначены», так что в каждой группе есть якорь — если
вопросы с этой формулировкой ровно те, которым правило дало единицу, порядок
верен. Проверка проходит в 16 группах из 17 многовариантных.

Где не проходит — группа не упорядочена вовсе, и вопросы различаются только тем,
что спрашивают. Под это в `fipi/practical.py` описаны два сценария («шины» и
«план квартиры»); сценарий «шины» сверен с позицией на 95 задачах, где есть оба
сигнала, и только потом применён к перемешанной группе. Группа без порядка и без
сценария сохраняет один якорь, остальное остаётся в корзине `1–5`.

## Три ловушки в разметке ФИПИ

Ради них и написан отдельный парсер:

1. **Картинок нет в HTML.** Они пишутся джаваскриптом через `document.write`
   внутри `ShowPictureQ(...)`, поэтому обычный DOM-парсер видит ноль изображений
   на странице, полной чертежей. Мы читаем аргументы вызовов.
2. **Формулы — это MathML** (`<m:math>` с префиксом `m:`, рендерит MathJax 4),
   не LaTeX и не картинки. `fipi/mathml.py` конвертирует их на входе.
3. **Ячейки условия содержат вложенные таблицы**, поэтому закрывающий `</TD>`
   нельзя найти нежадной регуляркой. Парсер считает глубину тегов.

Плюс мелочь: ответ приходит в **windows-1251**.

## Проверка ответов

Правильных ответов банк не отдаёт, но у него есть эндпоинт проверки. Если в
записи появилось поле `answer` (вы решили задачу сами или моделью), его можно
подтвердить:

```bash
python3 run.py verify --limit 100
```

Один запрос на задачу. Это подтверждение уже посчитанного ответа, а не способ
его добыть: перебором это всё равно не работает на дробных и длинных ответах,
а по нагрузке выглядит как атака на один публичный хост.

## Ключи ответов

Ту же проверку использует `solve`: сначала ответ считается локально, потом
подтверждается, и **сохраняются только подтверждённые**. Поэтому решателям
позволено ошибаться — ошибка стоит отклонённого кандидата, а не неверного
ключа в банке.

```bash
python3 run.py --delay 0.8 solve --choices --dry-run   # что уйдёт, без запросов
python3 run.py --delay 0.8 solve --choices             # партия
```

`--choices` дополнительно обходит задачи, у которых форма сама задаёт конечный
набор ответов (три кнопки — три кандидата). Свободный числовой ответ так не
берётся никогда.

Банк сильно клонирован, поэтому решатели кодируют **шаблон**, а не отдельную
задачу: 948 задач геометрии сводятся к сотне условий, различающихся только
числами.

| Модуль | Семья |
|---|---|
| `fipi/solver.py` | Арифметика: «Найдите значение выражения» |
| `fipi/equations.py` | Уравнения — коэффициенты снимаются замером в точках |
| `fipi/formulas.py` | Расчёт по формуле из условия |
| `fipi/probability.py` | Вероятность |
| `fipi/geometry.py` | Планиметрия 15–18, около семидесяти шаблонов |
| `fipi/squared_paper.py` | №18: ответ снимается с самого чертежа |
| `fipi/hints.py` | Кандидаты из внешнего каталога — только кандидаты |

На 18 августа 2026: **2574 ключа**, часть 1 закрыта на 86%.

### №18: ответ живёт в картинке

В условии нет ни одного числа — «изображена трапеция, найдите её площадь», —
поэтому чертёж читается: `fipi/raster.py` разбирает PNG и GIF (только
стандартная библиотека: `zlib` и разжатие LZW), `fipi/lattice.py` находит
сетку и вершины, `fipi/squared_paper.py` считает ответ.

Ключевое наблюдение: **сетка и фигура нарисованы одним цветом**, порогом их не
разделить. Зато линия сетки идёт через всю картинку, а сторона фигуры — нет,
поэтому тон колонки берётся не медианой, а перцентилем 0.9: длинная
вертикальная сторона тогда не выдаёт себя за бумагу. Пиксель считается
рисунком, если он темнее, чем были бы его колонка и строка без ничего.
Сторона, лежащая **на** линии сетки, видна только тем, что линия становится
толще, — такие отрезки проверяются рядом с линией, а не поверх неё. На
пересечениях двух линий не читается ничего: там бумага уже чёрная.

Вершины ищутся перебором пар узлов решётки: между парой проверяется, нарисован
ли штрих, и остаются только максимальные отрезки. Сторона, полностью съеденная
чёрной линией сетки, достраивается замыканием контура — невидимой может быть
только сторона, параллельная осям.

Из 154 задач так взят **81 ключ**. Не даются круги (сетка режет дугу на куски,
и они не всегда собираются обратно) и семейства, где вопрос называет буквы на
чертеже: «во сколько раз отрезок AB длиннее CD». Для них нужно читать подписи —
это отдельная работа.

### Кандидаты из внешнего каталога

`python3 run.py hints` ищет наши открытые задачи в стороннем каталоге ОГЭ и
складывает найденные числа в `out/hints.jsonl`. Это **кандидаты, а не ключи**:
чужое сюда не переносится — ни формулировка, ни разбор, ни картинка, только
число, и оно идёт той же дверью, что и всё остальное, — через проверку у ФИПИ.
В банк попадает наш собственный подтверждённый факт.

Сопоставление идёт по совпадению текста, и это его потолок: практический блок
клонирует один вопрос на десяток вариантов, отличающихся только общим условием.
Поэтому предлагается несколько ответов, а разбирается с ними проверялка. Выход
скромный и падает по мере ослабления правила: 44 подтверждения на 26 отказов
при строгом совпадении, 25 на 116 при сопоставлении по похожести. Дальше
ослаблять смысла нет — это уже нагрузка на чужой хост ради шума.

### Формулы, нарисованные картинкой

В **370 задачах банка** часть условия существует только как картинка: ФИПИ
экспортировал условие из Word вместе с формулой-картинкой, а числа на
координатной прямой сохранил отдельными файлами по 15×16 пикселей. В HTML на
этом месте остаётся пустой `<span>`, и в условии получается дыра — «Диагональ
ромба равна 28, а . Найдите площадь», «На прямой отмечены числа и .».
Ни текст, ни MathML этого значения не содержат.

Тем же вызовом `ShowPicture` рисуются и обычные чертежи, поэтому обёртка сама
по себе не решает ничего. Решают три признака (`_is_inline_picture`):

1. **Подсадка на базовую линию.** `<span style="position:relative;top:3.0pt">`
   — так завёрнут 541 фрагмент и ни одного чертежа.
2. **Слова на той же строке.** Картинка, у которой внутри её блока есть текст
   слева или справа, — часть предложения, как бы она ни называлась. Так
   находятся числа на координатной прямой: ФИПИ кладёт их под обычным именем
   `xs3qstsrc…`, неотличимым от чертежа.
3. **`innerimg*` внутри `<span>`.** Имя `innerimg` Word даёт картинке,
   вынутой из самого документа. В обёртке такая картинка всегда фрагмент:
   по всему банку самая высокая из них — 65 пикселей, тогда как чертежи с тем
   же именем стоят вне всякого `<span>` и начинаются со 144.

Голый `innerimg*` без обёртки оставлен чертежом сознательно: это прямоугольник
рядом с «Найдите площадь прямоугольника». Проверка правила на всём банке:
среди отправленных в текст нет ни одной картинки выше 70 пикселей, среди
оставленных в галерее — ни одной ниже 40.

Парсер ставит на место картинки markdown-картинку и складывает её путь в
`inline_images`; на сайте импортёр подменяет путь на нашу копию и убирает
картинку из галереи, чтобы формула не висела рядом с задачей отдельно.
938 картинок. Общий текст группы проходит ту же обработку — «шина имеет ширину
▩ мм и высоту боковины ▩» — и складывает свои пути в `group_inline_images`;
там картинка называется голым именем, а каталог задан отдельно в
`files_location`, поэтому путь достраивается до того же вида, что в галерее.

Решателю картинка ничего не даёт, поэтому для 53 задач геометрии значения
дополнительно переписаны с них текстом в `data/inline_math.json` (ключ —
короткий id задачи).

## Что не собирается

`cache/` и `out/` не попадают в git. Материал ФИПИ хранится локально: банк
собран для внутреннего использования, и класть копию заданий и схем в
репозиторий — это уже публикация. Сборка воспроизводится за десять минут.
