# Импортер открытого банка ОГЭ ФИПИ

Собирает задания по математике из [открытого банка ФИПИ](https://oge.fipi.ru/bank/index.php?proj=DE0E276E497AB3784C3FC4CC20248DC0),
раскладывает их **по номерам заданий экзамена (1–25)** и складывает результат в
`out/tasks.jsonl` плюс папку с картинками.

Сортировки по номерам у ФИПИ нет — банк размечен только по кодификатору. Её
восстановление и есть смысл этого инструмента.

Только стандартная библиотека Python 3.10+. Ставить нечего.

## Как запускать

```bash
cd tools/fipi

python3 run.py crawl     # 39 запросов, кладёт сырой HTML в cache/
python3 run.py build     # cache/ -> out/tasks.jsonl с номерами заданий
python3 run.py images    # 2765 схем -> out/images/<guid>/
python3 run.py stats     # отчёт по классификации
```

`crawl` кэширует страницы на диск. Повторный запуск читает кэш и в сеть не
ходит — `build` можно гонять сколько угодно, переписывая классификатор.
Чтобы обновить кэш: `python3 run.py crawl --refresh`.

Полный проход занимает пару минут на `crawl` и около десяти на `images`.

### Полезные флаги

```bash
python3 run.py --theme 7 crawl              # только геометрия
python3 run.py --theme 8.2 crawl            # только вероятность
python3 run.py --answer-kind ILI_STD_FULL crawl   # только часть 2
python3 run.py --delay 3 crawl              # медленнее, если ФИПИ тормозит
```

## Результат на полном банке

3884 задачи, 1577 из них со схемами (40.6%).

| Уверенность | Задач | Доля |
|---|---:|---:|
| `certain` | 2609 | 67.2% |
| `likely` | 545 | 14.0% |
| `ambiguous` | 729 | 18.8% |

Из 729 спорных **567 неразделимы в принципе**, а не из-за слабых правил:

- **315** — практический блок 1–5. В банке он расплющен: каждый из пяти
  вопросов лежит отдельной записью, и ничто не связывает их обратно в серию —
  ни общая картинка, ни номер группы. Позиция внутри блока не восстанавливается
  из того, что отдаёт ФИПИ.
- **252** — пара 23/25. Обе позиции это геометрия с развёрнутым ответом на одном
  и том же КЭС; спецификация различает их только уровнем сложности, которого в
  банке нет. Задание 24 отделяется чисто — по слову «докажите».

Остаётся около **160 задач (4%)**, где правила действительно не дотягивают:
в основном пары 16/17 и 15/16 в геометрии. Это материал для прохода моделью или
руками — в каждой записи лежит `classification.candidates` с коротким списком.

## Как устроена классификация

Три сигнала по убыванию надёжности, `fipi/classify.py`:

1. **Тип ответа.** «Развернутый ответ» встречается только в части 2, то есть
   ограничивает ответ номерами 20–25, а всё остальное — номерами 1–19.
   «Установление соответствия» в математике ОГЭ бывает практически только в №11.
2. **Текстовые сигнатуры.** Несколько позиций имеют фиксированную формулировку,
   которую банк повторяет сотнями: «на клетчатой бумаге» → №18, «Какое из
   следующих утверждений является истинным» → №19, «Пользуясь этой формулой»
   → №12.
3. **Подтемы кодификатора.** Спецификация 2026 (`research/fipi-2026/spec.txt`)
   задаёт КЭС для каждой позиции; обратная таблица превращает код в список
   кандидатов. Банк размечает большинство задач до подтемы («7.4 Окружность и
   круг»), и это самый сильный сигнал: 7.2 → №15, 7.3 → №17, 7.4 → №16,
   3.1 → №9, 3.2 → №13, 2.1 → №12.

Ничьи внутри геометрии добиваются подсчётом ключевых слов. Что не разошлось —
помечается `ambiguous`, а не угадывается.

## Три ловушки в разметке ФИПИ

Ради них и написан отдельный парсер:

1. **Картинок нет в HTML.** Они пишутся джаваскриптом через `document.write`
   внутри `ShowPictureQ(...)`, поэтому обычный DOM-парсер видит ноль изображений
   на странице, полной чертежей. Мы читаем аргументы вызовов.
2. **Формулы — это MathML** (`<m:math>` с префиксом `m:`, рендерит MathJax 4),
   не LaTeX и не картинки. `fipi/mathml.py` конвертирует их на входе.
3. **Ячейки условия содержат вложенные таблицы**, поэтому закрывающий `</TD>`
   нельзя найти нежадной регуляркой. Парсер считает глубину тегов.

Плюс мелочь: ответ приходит в **windows-1251**.

## Проверка ответов

Правильных ответов банк не отдаёт, но у него есть эндпоинт проверки. Если в
записи появилось поле `answer` (вы решили задачу сами или моделью), его можно
подтвердить:

```bash
python3 run.py verify --limit 100
```

Один запрос на задачу. Это подтверждение уже посчитанного ответа, а не способ
его добыть: перебором это всё равно не работает на дробных и длинных ответах,
а по нагрузке выглядит как атака на один публичный хост.

## Ключи ответов

Ту же проверку использует `solve`: сначала ответ считается локально, потом
подтверждается, и **сохраняются только подтверждённые**. Поэтому решателям
позволено ошибаться — ошибка стоит отклонённого кандидата, а не неверного
ключа в банке.

```bash
python3 run.py --delay 0.8 solve --choices --dry-run   # что уйдёт, без запросов
python3 run.py --delay 0.8 solve --choices             # партия
```

`--choices` дополнительно обходит задачи, у которых форма сама задаёт конечный
набор ответов (три кнопки — три кандидата). Свободный числовой ответ так не
берётся никогда.

Банк сильно клонирован, поэтому решатели кодируют **шаблон**, а не отдельную
задачу: 948 задач геометрии сводятся к сотне условий, различающихся только
числами.

| Модуль | Семья |
|---|---|
| `fipi/solver.py` | Арифметика: «Найдите значение выражения» |
| `fipi/equations.py` | Уравнения — коэффициенты снимаются замером в точках |
| `fipi/formulas.py` | Расчёт по формуле из условия |
| `fipi/probability.py` | Вероятность |
| `fipi/geometry.py` | Планиметрия 15–18, около семидесяти шаблонов |

### Формулы, нарисованные картинкой

В **193 задачах банка** часть условия существует только как inline-GIF
(`innerimgN.gif`): ФИПИ экспортировал их из Word вместе с формулой-картинкой.
В HTML на этом месте остаётся пустой `<span style="position:relative">`, и в
условии получается дыра — «Диагональ ромба равна 28, а . Найдите площадь».
Ни текст, ни MathML этого значения не содержат.

Для 53 задач геометрии значения переписаны с самих картинок в
`data/inline_math.json` (ключ — короткий id задачи). Остальные 140 задач —
номера 10, 12, 20 — так и остаются с дырой **и в условии на сайте**: это не
проблема ключей, а дефект отображения, который чинится в `parse.py`.

## Что не собирается

`cache/` и `out/` не попадают в git. Материал ФИПИ хранится локально: банк
собран для внутреннего использования, и класть копию заданий и схем в
репозиторий — это уже публикация. Сборка воспроизводится за десять минут.
